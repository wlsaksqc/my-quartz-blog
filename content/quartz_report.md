## 📌 개요
본 문서는 로컬 환경(Windows 11, 물리 드라이브 `D:\`)에서 Obsidian과 연동하여 동작하는 **Quartz v5** 블로그 엔진을 구축하고, 이를 **Cloudflare Pages**를 통해 인터넷에 최종 배포하는 과정 전반과 발생했던 주요 기술적 문제점 및 해결 방안을 상세히 기록한 보고서입니다.

---

## ⚙️ 1. 프로그램 설치 목적 및 명령어 명세

### 1) 핵심 설치 프로그램 및 목적
* **Node.js (v22 이상)**: Quartz는 React 및 TypeScript 기반의 정적 사이트 생성기(SSG)입니다. 이를 실행하고 빌드하기 위한 핵심 JavaScript 런타임 환경입니다.
* **Git**: 작성한 글과 블로그 테마 소스코드를 관리하고 GitHub 저장소로 안전하게 업로드(Push)하기 위한 분산 버전 관리 도구입니다.
* **Obsidian (로컬 에디터)**: 마크다운(.md) 기반의 개인 지식 관리 에디터로, 이곳에 쓴 글이 블로그의 콘텐츠가 됩니다.
* **Cloudflare Pages**: 깃허브 저장소와 실시간으로 동기화되어 소스코드가 수정되어 올라갈 때마다 자동으로 블로그를 무상으로 빌드하고 글로벌 CDN 네트워크에 배포해 주는 호스팅 서비스입니다.

### 2) 주요 설정 명령어 해설
* `git init`: 백지 상태의 새 로컬 저장소를 생성하여 서브모듈 등 이전 캐시 이력을 깨끗하게 청소합니다.
* `git checkout -b v5`: Cloudflare Pages와 연동할 프로덕션 브랜치 명을 `v5`로 생성 및 지정합니다.
* `npx quartz create --strategy new --template default`: 순수한 Quartz 기본 물리 템플릿과 설정 파일을 로컬 프로젝트에 재구성(Bootstrap)하여 꼬인 외부 가상 참조 링크 문제를 극복합니다.

## 🚨 2. 배포 과정 중 발생한 문제점 (Troubleshooting) 및 해결 방안

진행 과정에서 총 3가지의 핵심 문제로 빌드가 실패했으며, 이를 단계별로 우회/해결하여 정상화시켰습니다.

### ❌ Issue 1. 구글 가상 드라이브(G:\)로 인한 파일 잠금 에러
* **증상**: `npm clean-install` 수행 중 `EBADF (Bad file descriptor)` 에러가 발생하며 프로세스 차단.
* **원인**: 구글 드라이브(동기화 가상 폴더)의 실시간 클라우드 동기화 락(Lock)이 Node.js가 임시 파일을 쓰고 삭제하는 속도와 충돌하여 에러 유발.
* **해결 방안**: 로컬 물리 드라이브인 `D:\깃 클론(Clone)` 디렉토리로 작업 공간을 완전히 이전하여 충돌 해결.

### ❌ Issue 2. Quartz 템플릿 내 '서브모듈(Submodules)' 연결 끊김 현상
* **증상**: Cloudflare 빌드 초입의 `Cloning repository` 단계에서 `fatal: No url found for submodule path...` 에러로 빌드 실패.
* **원인**: Quartz 프레임워크가 수십 개의 플러그인 폴더를 내부 저장소가 아닌, 외부 개발자의 깃 주소(Submodule)에 가상으로 연결해 두어 발생. 해당 링크 중 주소가 폭파되거나 바뀐 링크가 있어 서버 복제 시 중단됨.
* **해결 방안**: 
  1. 로컬 저장소 내부의 숨겨진 `.gitmodules` 파일 완전 삭제.
  2. `.quartz/plugins/` 내부 하위 폴더에 숨어있던 외부 깃 제어 파일(`.git/` 폴더)들을 명령어로 모두 박멸.
  3. 모든 가상 링크(gitlink)를 일반 물리 텍스트 파일 폴더 구조로 강등 전환하여 재커밋.

### ❌ Issue 3. `.gitignore`에 의한 `.quartz` 폴더 추적 누락
* **증상**: 서브모듈 캐시를 제거한 뒤 배포하자 `Could not resolve "../../.quartz/plugins"` 파일 누락 에러 발생.
* **원인**: `.gitignore` 설정 파일에 기본적으로 `.quartz/` 폴더가 추적 제외(Ignored) 상태로 묶여 있어, 깃허브에 빈 폴더 껍데기만 올라감.
* **해결 방안**: 로컬 `.gitignore` 파일에서 `.quartz/` 제한 항목을 완전히 제거하고 `git add -f .quartz/` 명령을 사용해 실제 물리 코드 파일들을 깃허브 원격 서버로 완벽하게 전송 완료.

## 📈 3. 최종 결과
위 문제들을 모두 물리적으로 해결하여 깃 역사를 초기화한 후 최종 강제 푸시(`git push -f origin v5`)를 수행하였으며, 그 결과 **Cloudflare Pages 빌드가 에러 없이 한 번에 성공(Success: Your site was deployed!)**하여 정상적인 서비스 주소로 블로그가 안전하게 배포 완료되었습니다.

앞으로 옵시디언 에디터의 `content` 폴더에 원하는 글을 추가한 뒤 깃허브로 푸시해 주면 자동으로 블로그 글이 갱신됩니다.
